# 第 5 页 · 亮点一：MCP loopback —— 让 Agent 自己连自己

**放**：一张调用链图 + "为什么同进程绕一次 HTTP"的答案。

**讲什么（这是你的招牌，务必讲透）**：

> 最有意思的是 MCP loopback。Agent 读本地文档时，我**不走同进程直接调方法的捷径**，而是让它作为 MCP Client 连接本机自己的 MCP Server，完整走 SSE + JSON-RPC 握手。

```
LLM 决定调 mcp.loopback.local.read_document
  → ToolRegistry 识别 mcp. 前缀
  → McpToolProxy 连本机 /mcp/message
  → 同 JVM 的 MCP Server 处理
  → 结果经 SSE 推回
```

**必答追问（面试官几乎一定会问）**：

> 确实多一次本机回环，实测 5ms 以内，可忽略。但换来三件事：
> 1. **协议栈是真通的**——Server/Client 两套代码都被真实验证
> 2. **扩展零成本**——接第三方 MCP Server 只需加一个配置
> 3. **它暴露了真实 bug**——正因走真协议，我才发现相对 URI 的 bug，走捷径会潜伏到接外部服务器那天

**数据**：loopback 回环 < 5ms

# 第 6 页 · 亮点二：Reflexion × CRAG 双闭环

**放**：一张表（两类失败 → 两个机制）。

**讲什么**：

> Agent 有两类失败，大多数人只处理一类：

| 失败类型 | 现象 | 我的机制 |
|---|---|---|
| 工具**坏了** | 抛异常/参数错/工具不存在 | **Reflexion**：错误回灌自纠 |
| 工具**好了但没查到好东西** | 检索成功但质量差 | **CRAG**：改写重检索/降级明示 |

**重点讲第二类（更有区分度）**：

> 第二类最危险：检索返回一堆低相关片段，LLM 会拿着**编出看似有据的错误答案**——比明确说"我不知道"危险得多。
>
> 我的做法是 CRAG：检索完自评质量，低质就改写重检索，仍不行就在结果里塞一个**结构化降级信号**，强制模型明示"未找到强相关笔记，以下基于通用知识"。

**点睛**：把"提示词软约束"升级成"运行时硬闭环"——质量评估在服务端确定性完成，不赌模型自觉。

# 第 7 页 · 亮点三：工具运行时可见性（分层遮蔽）

**放**：四层 scope 链图 + 一句话点出修了什么 bug。

**讲什么（这是你最新、最前沿的贡献，讲出"参考了 DeepSeek Harness"的出处）**：

> 个人场景有个特点：同一个用户在不同模式下，工具的权限应该不同。我在"学习"模式不想让 Agent 改任务，在"执行"模式又需要。
>
> 原来的做法是给工具打 tag 按模式过滤，但我发现两个问题：
> 1. tag 过滤是 OR 语义，**只能"放行"不能"禁止"**——`note.create` 同时带 note 和 write 两个 tag，学习模式放行了 note，它照样能写笔记（这是个真实 bug）
> 2. 更关键的是，**过滤只影响给 LLM 的列表，不影响执行**——模型凭记忆照样能调通

**方案**：

> 我参考了 DeepSeek Harness 的分层工具遮蔽，做了四层 scope 链：全局 → 模式 → 角色 → 会话。运行时实时算出"当前能看到哪些工具"，支持显式 deny，并且每个工具都能给出"为什么不可见"的决策链。

**点睛（体现不是照搬）**：

> DSH 的分层遮蔽其实解决两件事：插件化实现替换、可见性收窄。我只需要后者——我的工具是注解扫描的，一个名字唯一实现，硬做"替换"就是过度设计。所以我刻意裁剪掉了它，只保留收窄 + deny。

**串起体系（金句）**：

> 这和我之前的 Reflexion 封禁组成**两层权限治理**：可见性决定"你本来能碰什么"，Reflexion 封禁决定"你这轮已经把什么碰坏了"。

# 第 8 页 · 亮点四：轮次收尾归因（TurnOutcome）

**放**：一个"粘性降级标记"的示意 + 修正了什么指标。

**讲什么（与第 7 页呼应，体现体系化思维）**：

> 我另一个发现是：系统里有大量的**静默信息丢失**。比如工具结果超过 4000 字符就硬截断，切掉了 LLM 不知道、用户更不知道。
>
> 我参考 DSH 的一个细节——它的 max-tokens 状态是**粘性**的，某一步被截断过，后面正常完成也不能把结束原因覆盖回"正常"。
>
> 我把这个思路落地成"粘性降级标记"：本轮只要发生过截断、CRAG 降级、或子代理结论被切，就置一个**只能置位不能清除**的标记。

**修正指标（体现严谨）**：

> 这顺带修正了一个被高估的指标——原来的收敛率把"中途丢过数据但最后蒙对了"也算成正常收敛。现在多了一个 `cleanConvergenceRate`，两者的差值就是被高估的部分。

**价值一句话**：

> 在还没能力"不丢信息"之前，先做到"不隐瞒信息丢失"。

# 第 9 页 · 亮点五：上下文工程（子代理 + 前缀缓存）

**放**：两个机制各一张小图。

**讲什么（两个都讲，但控制篇幅）**：

**① 子代理隔离**：

> 主对话上下文是稀缺资源。Agent 读了 50 页 PDF，原文全进历史，后面就被挤爆。我做了 Orchestrator-Worker：规划/复盘/检索三个角色在**独立上下文**跑完整 ReAct，只回压缩后的结论（≤4000 字符）。并做了并行 fan-out，超时的 worker 降级标注而不整体失败。

**② 前缀缓存 + 字节稳定化**：

> 每步 ReAct 都要重复构造 system prompt。我把前缀拆出来缓存复用。关键是**字节稳定化**——上游的 automatic prefix caching 按前缀字节完全一致才命中，我修了两个隐蔽问题：日期从精确时间改成天级、工具 schema 输出排序。然后用 usage 字段**闭环验证**缓存真的命中了。

**数据**：上游 prompt cache 命中 token 占比（跑一遍记录真实数字）

# 第 11 页 · 亮点七：知识仓库（把约定变门禁）⚡

**放**：一张五期能力的时间线 + 一句方法论金句。

**一句话核心**：

> 我把「学习一个技术体系」这件事工程化了。核心方法论一句话：**把靠人自觉的约定，逐条升级成机器门禁。**

**五期能力（一条线讲下来）**：

| 期 | 能力 | 一条可讲的取舍 |
|---|---|---|
| P0 | Git 仓库四级索引 | MySQL 是**可丢弃的派生索引**，Git 是权威源 |
| P1 | 验证闭环（checkpoint） | **预测门禁**：先写预测再动手，因为"改完再解释"人会为结果编理由 |
| P2 | 沉淀 + PR + 知识 CI | 写入白名单只含 `docs/notes/`——改既有 guide 在结构上**不可能** |
| P3 | 缺口三源合流 | 缺口只能来自**行为证据**，刻意不提供 `gap.create` 工具 |
| P4 | 蒸馏 + 定线 | 蒸馏**先看后写**；定线一次 LLM 都不调（可核对 > 更聪明） |

**选 1~2 个门禁展开（口头）**：

1. **示例门禁是执行层拒绝**：沉淀时源有代码块而模型把笔记删成摘要 → 直接拒绝写入。理由：模型天然倾向压缩，被压掉的恰是半年后还能看懂的示例。且有指标自证——`exampleGateRejections` 一旦非 0，就证明"只靠 prompt 提醒不够"。
2. **止损线判据是"解析器真能抽出"**：不是"有那个小节就行"。抽不出术语的止损线在系统里静默失效，从文件本身看不出来。

**金句**：

> prompt 提醒失效时是静默的，门禁失效时会大声拒绝——前者让你很久以后才发现内容坏了，后者当场就拦住。

# 第 13 页 · 踩坑与反思（最有说服力的一页）

**放**：2~3 个真实 bug，每个一行现象 + 一句根因。

**讲什么（挑 2 个讲，编不出来才有分量）**：

**坑 1 · MCP loopback 永远连不上（相对 URI）**：
> 现象是 Agent 说"读不了本地文件"，但 curl 全对。根因是服务端返回的 endpoint 是**相对路径**，Java HttpClient 不接受相对 URI，握手一直失败，而日志写的是"将重试"——看起来会自愈其实不会。这坑让我学会用 curl 分治定位是 Server 还是 Client 的问题。

**坑 2 · CRAG 链路"看起来通了其实断了"**：
> 三个组件单测全对，但检索质量差时 Agent 还是编造。根因是降级信号只在零命中时返回，而"有命中但质量差"走不进那个分支。**每个组件单独都对，但组件间的信息传递断了**——这是单测的盲区，所以我后来专门加了端到端断言。

**收尾金句**：

> 这两个坑教会我两件事：一是做了优化必须能证明有效；二是可观测性必须有消费方，否则指标恒为 0 也不会被发现。
