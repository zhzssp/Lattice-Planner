## 三、亮点 1 · MCP loopback（最重要，2 页）

### 3.1 一句话核心

> 让 Agent 通过本机回环，**真正走 MCP 协议**访问自己的本地文件服务，而不是同进程直接调方法的捷径。

### 3.2 页面 1：调用链图（视觉主体）

给 AI 的图结构说明（建议画成 6 个节点 + 箭头的纵向链路图）：

```
LLM 决定调 mcp.loopback.local.read_document
        │
        ▼
ToolRegistry.invoke() 识别 "mcp." 前缀
        │
        ▼
McpToolProxy 解析 serverName=loopback
        │
        ▼
POST localhost:8080/mcp/message（JSON-RPC: tools/call）
        │
        ▼
[同一 JVM] McpSseEndpoint 处理
        │
        ▼
结果经 SSE 流式推回 LLM
```

**图的关键标注**（AI 务必在图上标出）：
- 中间那条虚线框标注：**"同一 JVM，仍走 HTTP + SSE + JSON-RPC"**
- 底部一句话：**"多一次本机回环（<5ms），换来协议栈完整复用"**

### 3.3 页面 2：为什么绕这一下（三栏对照）

给 AI 的三栏表结构：

| 收益 | 展开说明（文案） |
|---|---|
| ① 协议栈真通 | Server 和 Client 两套代码（SSE 建连、initialize 握手、tools/list 发现、tools/call 调用）都被这条链路真实验证，不是摆设 |
| ② 扩展零成本 | 接第三方 MCP Server 只需配置加一条，代码路径完全一样，工具自动以 `mcp.<server>.<tool>` 出现 |
| ③ 暴露真实 bug | 正因走真协议，才发现服务端返回 endpoint 是相对路径、Java HttpClient 不接受的 bug；走捷径会潜伏到接外部服务器那天 |

**底部结论一行**：

> 这是一个关于「抽象边界」的设计选择——宁愿多 5ms 回环，也要让协议栈真实可用。

### 3.4 给 AI 的"必答追问"预案（做成 PPT 备注，不一定要上屏）

- 问"同进程为什么绕 HTTP" → 上面三栏表
- 问"开销多少" → 实测 <5ms，相比文档解析和 LLM 摘要可忽略

## 四、亮点 2 · Reflexion × CRAG 双闭环（2 页）

### 4.1 一句话核心

> Agent 有两类失败，大多数人只处理一类；我两类都做了，且都做成**运行时硬闭环**而非提示词软约束。

### 4.2 页面 1：两类失败对照表（视觉主体）

给 AI 的表格：

| 失败类型 | 现象 | 传统做法 | 我的机制 |
|---|---|---|---|
| 工具**坏了** | 抛异常/参数错/工具不存在 | 让 LLM 自己看错误重试 | **Reflexion**：按失败模式注入策略 + 失败超阈值强制封禁 |
| 工具**好了但没查到好东西** | 检索成功但质量差 | 提示词里写"质量差要说明" | **CRAG**：自评质量 → 改写重检索 → 结构化降级信号 |

**关键标注**（AI 务必在表格下方加这一行）：

> 第二类比第一类更危险：检索返回低相关片段，LLM 会**编出看似有据的错误答案**，比明确说"我不知道"危险得多。

### 4.3 页面 2：两个机制的"硬闭环"本质

给 AI 的两个并列说明块：

**Reflexion 的深度（失败模式分类）**：
- 把失败分成 6 类：参数错 / 资源不存在 / 权限拒绝 / 用户拒绝 / 工具幻觉 / 偶发故障
- 核心洞察：**可重试性**是分类主轴。权限拒绝、用户拒绝、工具不存在这些"确定性失败"**一次即封禁**，不浪费第二步去证明它还会失败
- 两层设计：建议层（注入策略提示）+ 执行层强制（封禁后模型再调直接短路返回，不真正执行）

**CRAG 的深度（结构化降级信号）**：
- 检索完按融合分数分级：≥0.6 直接用 / 0.4~0.6 改写重检索 / <0.4 改写仍不行就降级
- 降级时在结果里塞一个**给 LLM 读的行动指令**（不是给人看的）："请在答复首句明示：未找到强相关笔记，以下基于通用知识"
- 本质：**质量评估在服务端确定性完成，不赌模型自觉遵守提示词**

**底部结论一行**：

> 核心方法论：把"提示词软约束"升级为"运行时硬闭环"。

## 五、亮点 3 · 工具分层遮蔽 + TurnOutcome（2 页，你的原创贡献）

### 5.1 一句话核心

> 个人场景的 Agent 需要**动态的权限边界**和**诚实的信息丢失声明**，我参考 DeepSeek Harness 做了两个机制，并刻意裁剪掉不适合自己场景的部分。

### 5.2 页面 1：工具分层遮蔽（四层 scope 图 + 一个 bug）

给 AI 的四层图（纵向堆叠，越往下优先级越高）：

```
┌ GLOBAL  全局：全量工具注册表 ─────────────┐
├ MODE    模式：执行/学习/规划/复盘 的权限边界 │
├ ROLE    角色：规划/复盘/检索 子代理         │
└ SESSION 会话：用户临时意愿（pin/deny）      ┘
```

**必放的"bug 揭示"块（这是亮点，不是背景）**：

> 原做法是给工具打 tag 按模式过滤，但有 bug：
> - `note.create` 同时带 `note` 和 `write` 两个 tag，学习模式放行了 `note`，它**照样能写笔记**（OR 语义只能"放行"不能"禁止"）
> - 更关键：过滤只影响给 LLM 的列表，**不影响执行**——模型凭记忆照样能调通

**方案说明（AI 写成两行）**：
- 支持显式 `deny`（禁止）+ `pin`（破例），运行时实时算出"当前能看到哪些工具"
- 每个工具都能给出**可解释的决策链**（为什么可见/不可见）

**底部结论（金句，AI 务必保留）**：

> 可见性决定"你本来能碰什么"，Reflexion 封禁决定"你这轮已经把什么碰坏了"——两层权限治理。

### 5.3 页面 2：TurnOutcome 粘性降级标记

给 AI 的一个"信号累积"示意图：

```
本轮执行过程中，任何一步发生：
  ├─ 工具结果超 4000 字符被截断 ──┐
  ├─ 检索质量差（CRAG 降级）    ──┼─→ degraded = true（粘性，不可清除）
  ├─ 子代理结论被截断          ──┤
  └─ 工具被封禁               ──┘
        │
        ▼
轮次结束：如果答复里没提"信息可能不完整"，就强制补一句
```

**两个关键点（AI 写文案时强调）**：

1. **粘性**：参考 DSH 的"max-tokens 状态粘性"——一旦发生过信息丢失，后面正常完成也不能覆盖回"干净完成"
2. **修正指标**：原来的收敛率把"中途丢过数据但最后蒙对了"也算正常收敛，是**偏乐观**的；现在多了 `cleanConvergenceRate`，差值就是被高估的部分

**底部结论一行**：

> 在还没能力"不丢信息"之前，先做到"不隐瞒信息丢失"。

### 5.4 给 AI 的"刻意裁剪"话术（体现不是照搬，务必上屏或备注）

> 我参考了 DeepSeek Harness，但**刻意裁剪**：它的分层遮蔽还解决"插件化实现替换"，而我的工具是注解扫描、一个名字唯一实现，硬做替换就是过度设计。所以只保留"收窄 + deny"。

## 六、其余内容的简化指令

给 AI：以下内容各 1 页或合并，不要展开细节。

### 6.1 技术总览页

### 6.2 评测体系页（1 页，这是"工程化"证明）
- 核心难点：LLM 非确定，无法写传统断言
- 解法：把可替换点设在 **HTTP 边界**（录制/回放），固定"模型说了什么"，其余全真实执行
- 指标：收敛率 / 幻觉率 / 步数 P50-P95
- 一句：**这是所有优化的"度量衡"**

### 6.3 踩坑页（1 页，最有说服力）

- CRAG 信号只在零命中时返回 → 组件间信息传递断了（单测盲区）

### 6.4 其他模块速览（合并 1 页）
RAG Serving（语义缓存）、MCP Server 双向、多模型路由、主动式 Agent——各一句话。

### 6.5 收尾页
