# 长期记忆机制补全 · 实现报告

> 范围：阶段一（打通归档触发）+ 阶段二（与 RAG 隔离）
> 目标：让「写不通」的长期记忆真正闭环，并防止记忆碎片污染个人知识库 RAG 检索。

---

## 一、背景与问题

补全前，Agent 的记忆机制是「读通、写不通」的半成品：

| 能力 | 状态（补全前） | 说明 |
|---|---|---|
| 短期记忆 `ConversationMemory` | ✅ 已接入 | 进程内滑动窗口（30 条），每轮 `append`，`PromptBuilder` 拼入 history |
| 长期记忆读 `snippetFor` | ✅ 已接入 | 取最近 5 条 `AGENT_MEMO` 注入系统 Prompt |
| 长期记忆写 `archive` | ❌ **死代码** | **全代码库无任何调用方** |

**核心缺陷链：** `archive()` 从未被触发 → `AGENT_MEMO` 表恒为空 → `snippetFor` 恒返回空串 → Prompt 中「用户长期记忆」永远是「(暂无)」。配置项 `agent.chat.session-idle-archive-minutes=30` 也无任何 Java 代码读取（悬空配置）。

**附带隐患：** `archive()` 走 `noteService.create()` 会发布 `NotePersistedEvent` → `NoteIndexService.rebuildForNote` **不区分类型照样向量化**，一旦归档生效，`AGENT_MEMO` 会混进 `kb.semantic_search` 结果污染「我的笔记」检索。

---

## 二、阶段一：打通归档触发（写入闭环）

让「会话空闲」时自动调用 `archive()`。采用**空闲判定**而非「连接关闭即归档」，以容忍页面刷新 / 短暂断线重连，避免过早切断未结束的对话。

### 改动清单

| # | 文件 | 改动 |
|---|---|---|
| 1 | `runtime/ConversationMemory.java` | 新增 `lastActiveAt` 时间戳；`append` 时更新、`clear` 时移除；新增 `lastActiveAt(sid)` / `sessionIds()` / `idleSessions(Duration)` |
| 2 | `runtime/SessionArchiveScheduler.java`（新增） | `@Scheduled` 定时扫描空闲会话 → `archive()` → `clear()`；持有 `sid -> userId` 映射 |
| 3 | `chat/AgentChatWebSocketHandler.java` | 每轮 chat 调 `sessionArchiveScheduler.register(sid, userId)` 登记映射 |
| 4 | `runtime/LongTermMemoryService.java` | 凝练前过滤工具 trace 噪声（`isToolNoise`） |
| 6 | `resources/application.properties` | 新增 `agent.chat.archive-sweep-interval-ms=300000` |

### 关键设计

**1）活跃时间戳（`ConversationMemory`）**

```java
private final Map<String, Instant> lastActiveAt = new ConcurrentHashMap<>();
// append() 末尾：lastActiveAt.put(sid, Instant.now());
// clear()      ：lastActiveAt.remove(sid);

public Set<String> idleSessions(Duration idleThreshold) {
    Instant deadline = Instant.now().minus(idleThreshold);
    // 返回 lastActiveAt 早于 deadline 的会话
}
```

**2）归档调度器（`SessionArchiveScheduler`）**

```java
@Async
@Scheduled(fixedDelayString = "${agent.chat.archive-sweep-interval-ms:300000}")
public void sweep() {
    for (String sid : memory.idleSessions(Duration.ofMinutes(idleMinutes)))
        archiveSession(sid);
}

public void archiveSession(String sid) {
    Long uid = sessionUsers.remove(sid);        // 原子 remove 兜底去重
    List<Msg> history = memory.history(sid);
    memory.clear(sid);
    if (uid == null || history.isEmpty()) return;
    userRepository.findById(uid).ifPresent(u ->
        longTermMemoryService.archive(u, history));
}
```

- 复用既有 `agent.chat.session-idle-archive-minutes`（之前是悬空配置，现被读取生效）。
- `@Async` 让含 LLM 凝练的归档在已有 `pkm-` 线程池执行，不阻塞调度线程。
- `sessionUsers.remove` 的原子返回值兜底去重：并发 / 重复触发时第二次拿到 `null` 直接跳过。
- `@EnableScheduling` / `@EnableAsync` 已在 `MemorandumApplication` 开启，无需额外配置。

**3）`sid -> userId` 登记（`AgentChatWebSocketHandler`）**

```java
// 收到 chat、解析出 user 后：
sessionArchiveScheduler.register(sid, user.getId());
```

**4）工具噪声过滤（`LongTermMemoryService.archive`）**

`AgentOrchestrator.appendToolTrace` 每次工具调用会写入 2 条记忆（assistant 的 `{"tool":...}` JSON + user 的 `[tool_result ...]`）。凝练画像前剔除：

```java
private boolean isToolNoise(Msg m) {
    String c = m.content().trim();
    if (c.startsWith("[tool_result ")) return true;
    return "assistant".equals(m.role()) && c.startsWith("{\"tool\"");
}
// archive 中：过滤后若 dialogue 为空则不归档（纯工具会话不写画像）
```

## 三、阶段二：与 RAG 隔离（防污染）

在源头阻断 `AGENT_MEMO` 进入向量库——改动小、最彻底、且省 embedding 调用成本。

### 改动清单

| # | 文件 | 改动 |
|---|---|---|
| 5 | `pkm/service/NoteIndexService.java` | `rebuildForNote` 开头：`AGENT_MEMO` 仅重建双链、跳过向量化与缓存失效 |

```java
@Transactional
public void rebuildForNote(Note note) {
    if (note == null || note.getId() == null || note.getUser() == null) return;
    if (note.getType() == NoteType.AGENT_MEMO) {
        rebuildNoteLinks(note);   // 正文一般无 [[]]，等价 no-op
        return;                   // 不向量化、不失效缓存
    }
    rebuildNoteLinks(note);
    rebuildEmbeddings(note);
    vectorCache.invalidate(note.getUser().getId());
}
```

效果：`AGENT_MEMO` 永不落 `note_embedding` 表 → `kb.semantic_search` / `RagSearchService` 结果中不会出现长期记忆碎片，「我的笔记」检索保持纯净。

## 四、补全后的完整链路

```
用户对话 ── 每轮 ──► ConversationMemory.append(更新 lastActiveAt)
                          │
WS handler ── register ──► SessionArchiveScheduler(sid -> userId)
                          │
        每 5 分钟 sweep ──► idleSessions(空闲 ≥30min)
                          │
                  archiveSession：history ─过滤工具噪声─► LLM 凝练 3~6 行
                          │
                  noteService.create(AGENT_MEMO)
                          │
        NotePersistedEvent ──► NoteIndexService.rebuildForNote
                          │
                  AGENT_MEMO ──► 跳过向量化（阶段二隔离）✅
                          │
        下次对话 ──► snippetFor 取最近 5 条 AGENT_MEMO ──► 注入系统 Prompt ✅
```

至此长期记忆从「死代码」变为**可用闭环**，且与个人知识库 RAG 严格隔离。

## 五、配置项

| 配置 | 默认 | 含义 |
|---|---|---|
| `agent.chat.session-idle-archive-minutes` | `30` | 会话空闲多少分钟后归档（现已生效，此前悬空） |
| `agent.chat.archive-sweep-interval-ms` | `300000`（5min） | 空闲归档扫描间隔（fixedDelay） |

## 六、验证建议

1. 与 Agent 进行一段对话后停止操作，等待超过 `session-idle-archive-minutes`（验证时可临时调小，如 `2` 分钟）。
2. 观察日志：`[Agent] 长期记忆归档扫描：空闲会话数=...` 与 `[Agent] 会话 ... 已归档为长期记忆`。
3. 查库：`SELECT * FROM note WHERE type='AGENT_MEMO'` 应出现凝练条目；`note_embedding` 中**不应**有对应 chunk。
4. 开启新会话，确认系统 Prompt 的「用户长期记忆」段已带入上次画像。
5. 用 `kb.semantic_search` 检索，确认结果不含 `AGENT_MEMO` 内容。
