# 一、这次摸排的结论

## 1.1 总判断

想法的主回路是：

```
原始资料 → 学习路径 + 各站要点 → 目标/任务 → Agent 问答迭代
         → 纠正路径/要点、沉淀笔记 → Git → 直到 T(x) ≈ x
```

今天的 Codex 是：

```
接入已有 Git → 索引/体检 → 蒸馏出一篇草稿 → 定线给链接
            → 检验防假懂 → 缺口另开一套学习计划
```

零件大多跟想法同源（Git 权威、蒸馏带必学表、定线、沉淀要确认、检验先预测、缺口来自行为）。缺的是 **\(x\) 本身**：路径和要点不是一等状态，所以「改路径」「任务指回要点」「收敛」都没有操作对象。

## 1.2 已经对上想法的零件（不要拆）

| 零件 | 现在做什么 | 对应想法 |
|---|---|---|
| Git 工作副本 + `kb_*` 派生索引 | 文件是真相，索引可重建 | 资产在 Git |
| 蒸馏 | 读 `paper/*.pdf`，起草必学表 / 掌握标准 / 先跳过，create-only | 一次 \(T\) 的提议 |
| 定线 `RouteService` | 不调 LLM，按已有记录算「下一步」 | 收敛中的「现在干什么」 |
| 沉淀 `doc.write` + 回挂 | 认可才进 `docs/notes/` | 认可才进体系 |
| 检验 | 先预测再跑 | 防假懂（卡尺，不是主路径） |
| 缺口三源 | CRAG / 跳过召回 / 检验失败或预测错 | 行为证据 |
| 写入护栏 | `lattice/` 分支、guide 不能整篇改、示例门禁 | 未认可不进权威源 |

## 1.3 Idea §6 七步：支持程度

| 步 | 故事 | 程度 | 卡住的缺口 |
|---|---|---|---|
| 1 | 仓库放入论文/文档 | 有 | — |
| 2 | 抽出路径和要点，能改、能认可、写进 Git | 弱 | G1 G2 G5 |
| 3 | 路径生成 Dashboard 任务，能点回那一站 | 几乎无 | G3 G4 |
| 4 | 针对要点问答，认可的笔记挂回该要点 | 半套 | G5 G6 G8 |
| 5 | 顺序错了改路径，过时任务能看出来 | 无 | G5 G4 |
| 6 | 别处 `pull` 后软件展示跟着变 | 半套 | G9 |
| 7 | 反复后路径改动变小 = 收敛 | 无 | G10 G11 |

## 1.4 偏差怎么发生的

V2 把方法拆成源→蒸→线→做→验→沉→收之后，分期验收变成「这一环的工具能不能单独跑」，而不是「对话能不能改掉 \(x\)、任务会不会跟着动」。

一次具体分叉在 `RouteTools`：为避免与 `gap.to_learning_plan` **两套待办互相遗忘**，选择了定线**不**落任务。局部合理，但和 Idea 相反——正确收口是**只保留一份待办，由路径投影**，而不是两条都不成为主路径。

写入白名单同理：禁止整篇改 `docs/learning-guides/` 是对的（教材不可毁）；若路径/要点就写在这些文件里，等于删掉迭代面。方案是：**路径文件与教材分离，路径文件可受控改写，教材仍只许插一行速记。**

评测 cassette 也参与了分叉：CHAT/PLAN 必须 deny 整个 Codex 族，否则 schema 字节变、录制盒失效。这约束要保留，新能力进**新模式/新 tag**，不往 CHAT/PLAN 塞。

## 1.5 缺口一览

| ID | 缺口 | 优先 |
|---|---|---|
| G1 | 没有路径/要点这份一等状态 | P0 |
| G2 | 蒸馏只出一篇文，不抽出路径 | P0（接 G1） |
| G3 | 路径不驱动任务 | P0（接 G1） |
| G4 | 任务不能指回要点，路径一改看不出过时 | 与 G3 同做 |
| G5 | 对话改不了路径和要点 | P0（接 G1） |
| G6 | Codex 页无 Agent；UI 没有 study/curate/verify | P1 |
| G7 | plan 与 curate 把一条回路切成两半 | P1 |
| G8 | MySQL 笔记与 Git 笔记两套世界 | P1 |
| G9 | `git pull` 不更新软件展示 | P1 |
| G10 | 「收敛」没有产品形态 | P2 |
| G11 | 可见产品偏成执行器 | P1（壳） |
| G12 | 默认全关，日常等于没有 | P2 |

**实施顺序：G1 →（G2∥G5）→（G3+G4）→ G6+G7 → G9 → G8 → G11 → G10 → G12。**  
G1 不做，其余都是零件上再堆零件。不要先做 P5 综述/覆盖率。

# 二、所有缺口共用的硬约束

1. **Git 仍是权威源。** 路径、要点、认可笔记只以仓库文件为准；MySQL 只存派生索引和任务投影。删掉 `kb_station` / `kb_point` 能从路径文件重建。
2. **`docs/learning-guides/` 整篇仍不可写。** 迭代面是路径文件，不是教材。
3. **Agent 只能提议，人确认才 `path.apply`。** 与沉淀同一纪律。
4. **待办只有一份。** 路径投影任务；缺口不再另起一棵 Goal 树。
5. **CHAT / PLAN / LEARN / REFLECT 的工具 schema 字节不得因本方案改变**（评测 cassette）。新工具进新 tag / 新模式。
6. **VERIFY 仍是唯一 `exec` 模式。** 迭代对话不许跑脚本。

# 三、缺口与设计方案

## G1 · 路径 / 要点成为 Git 里的一等状态

### 现状

没有 `learning_path`、没有「站」、没有「要点」表。`RouteService` 的阶段表是现算的（有哪些 GUIDE、有没有 lab 目录、检验到哪一级）。README 只被切成检索切片。`kb_entity` 几乎只从「先跳过」清单来。

### 方案：独立的路径文件 + 窄口径解析 + 派生表

**权威文件**（默认 glob，可被 `.lattice/repo.yml` 覆盖）：

`docs/learning-path.md`

与教材分离：guide 继续讲机制；路径只回答顺序、依赖、每站要点。既有仓库若已把路线写在 `docs/README.md`，第一期做**只读导入**：解析器能读 README 阶段表，生成一份 `learning-path.md` 草稿（create-only），人核对后这份才成为权威。

**文件形态**（人可扫读，机器只认固定结构，手法同 `CheckpointParser` / `ScopeListParser`）：

```markdown
---
kind: learning-path
version: 3          # 人每次 apply 自增；用于任务投影对账
cursor: s2          # 当前站
---

## s1 · 读 IREE 编译流水线
- sources: `paper/iree.pdf`, `docs/learning-guides/iree-learning-guide.md`
- lab: `iree-lab/`
- next: s2

| id | 级别 | 要点 |
|----|------|------|
| s1.p1 | MUST | 能画出 compile 的主路径 |
| s1.p2 | SKIP | Codegen 后端细节，遇到再学 |

## s2 · …
```

解析规则（高置信、不跑 LLM）：

- `kind: learning-path` 才认；
- `## <id> · <title>` 为一站；
- 表格列必须含 `id` / `级别` / `要点`；级别只认 `MUST` / `SKIP`；
- `sources` / `lab` / `next` 为列表行。解析失败则整份文件标 `PARSE_FAILED`，**不静默丢行**。

**派生表**（索引，可丢）：

| 表 | 内容 | 重建键 |
|---|---|---|
| `kb_station` | repo_id, station_id, title, ordinal, sources_json, lab, next_json, cursor_flag | (repo_id, station_id) |
| `kb_point` | repo_id, station_id, point_id, level(MUST/SKIP), statement, source_span | (repo_id, point_id) |

`kb_entity` **不要**再用跳过清单冒充分母。SKIP 行写入 `kb_point`；MUST 才是掌握面的分母。P3 的 `ScopeRecallService` 改为：跳过召回的对象是 `kb_point(level=SKIP)`，不再单独为跳过词造 entity。

**索引时机：** 与现有 `RepoIndexer` 同一次 sync：路径文件 blobHash 变了就重解析。`RouteService.buildStages` 改为**读 `kb_station`**，不再猜 GUIDE 列表。没有路径文件时，阶段表显示「尚未抽出路径」，并链到蒸馏/导入，而不是用 guide 列表假充路径。

### 不做什么

- 不把路径嵌进 `learning-guides` 正文用 LLM 抽。
- 不在 MySQL 里手搓一份与 Git 无关的路线图。
- 不做知识地图可视化（P5 以后）。

### 验收

仓库里有一份能解析的 `docs/learning-path.md`；sync 后 `kb_station` / `kb_point` 行数与文件一致；改文件再 sync，展示变；删索引全量重建，行数恢复。没有该文件时 UI 不假装已有路径。

## G2 · 蒸馏同时产出「路径提议」，而不只是一篇 guide

### 现状

`DistillService` map-reduce 只渲染 guide markdown，create-only 落到 `docs/paper-notes/`。必学表在文里，软件不当作要点账。

### 方案：一次蒸馏两个产物，落盘仍分目录

在现有 reduce 协议里**加第五段**（固定分隔符，与现有四段同级）：

```
### PATH_DELTA
stations: …
points: …
```

- `GuideTemplate` 仍写 `docs/paper-notes/`（create-only，不变）；
- `PathDeltaRenderer` 把 PATH_DELTA 变成对 `docs/learning-path.md` 的 **unified diff / 补丁对象**，**不直接覆盖**。没有路径文件则生成全文草稿（create-only）；已有则只追加/改声明过的 `station_id`。
- 人在定线页或对话里点「认可并写入路径」才走 G5 的 `path.apply`。
- 解析失败则蒸馏仍可保存 paper-note，但 UI 明示「未抽出可应用的路径」，不得把 guide 正文假装成路径。

`ExamService` 出题时若 guide 声明了 `station_id`，checkpoint front-matter 写上该 id，便于 G3 投影与 G10 统计。不出题也可以，不阻塞 G2。

### 不做什么

- 不让蒸馏直接 `REPLACE` 已有 `learning-path.md`。
- 不把 PATH_DELTA 失败当成整次蒸馏失败（文可以留，路径再跑）。

### 验收

对一份 PDF 蒸馏：paper-note 新建成功；PATH_DELTA 可预览；人确认后路径文件出现对应站和 MUST/SKIP 行；未确认则路径文件字节不变。

## G3 · 路径驱动任务（推翻「定线不落任务」）

### 现状

`RouteTools` 故意不把定线变成 Goal/Task，以免与 `gap.to_learning_plan` 两套待办。Dashboard 任务与学习要点无关。

### 方案：任务是路径的投影，不是第二条计划

**单一待办：** Dashboard 上与本仓库相关的学习任务，只来自 `PathProjector`。

投影规则：

1. 读取 `cursor` 及后续 \(N\) 站（默认当前站 + 下一站，\(N\) 可配）。
2. 每个 **MUST** 且尚未满足掌握判据的 `kb_point` → 一条 `Task`。
3. 标题用要点原文；描述里写站名、sources、链到 `/codex` 该站。
4. 掌握判据（有一个即视为该要点可不再投影）：
   - 绑定了 checkpoint 且 L2 通过；或
   - 任务 `DONE` 且人未再把该要点标回 MUST 未完成。

**关掉** `gap.to_learning_plan` 对 `PlannerAgentService.apply` 的直接建树。缺口转计划改为：打开一条 **路径补丁草稿**（新增 MUST 或插入一站），走 `path.apply`，再投影。P3 工具保留名字可以，语义必须改；旧 cassette 若录了「建 Goal」，该用例要重录或移出默认套件，并在评测指南写明。

Goal：每个接入的学习仓库对应 **一个** 学习目标（名称=仓库名或路径标题），任务都挂这棵树。不要每个缺口一棵树。

`route.next` 的第一条行动改为「Dashboard 今日任务即当前站 MUST」，href 可以同时给 Codex 站页和 `/dashboard`。

### 不做什么

- 不保留「定线待办」和「Dashboard 待办」两份清单。
- 不给 CURATE 开放通用 `task.create`（见 G7）。

### 验收

路径 cursor 在 s1，Dashboard 只出现 s1（及配置的下一站）的 MUST 任务；把 cursor 改到 s2 并 apply 后，s1 未完成任务标过时（G4），s2 任务出现。缺口「转计划」不再新建第二棵 Goal。

## G4 · 任务指回要点；路径一改能看出过时任务

### 现状

`Goal` / `Task`（`memo`）无 Codex 外键。`Link` 只有 TASK/NOTE/GOAL。仅 `kb_gap.goal_id` 单向。

### 方案：投影表 + STALE，不把 Git 路径 id 塞进 memo 上帝列

新表 `kb_task_projection`（派生，可重建）：

| 列 | 含义 |
|---|---|
| task_id | 现有 memo.id |
| repo_id | |
| path_version | 投影时路径文件的 `version` |
| station_id / point_id | |
| state | ACTIVE / STALE / SATISFIED |

每次 `path.apply` 或 sync 到新 `version`：

- point 仍在、仍 MUST、仍在窗口内 → ACTIVE（更新 version）；
- point 删除、改为 SKIP、或站被移到 cursor 之后且任务未完成 → **STALE**；
- 已 DONE 且 point 仍在 → SATISFIED。

Dashboard：STALE 任务单独一截「路径已改，这些不再是下一站」，可归档或忽略。点任务标题跳到 Codex 该站（query: `station` / `point`）。

重建索引：若 memo 还在但投影行丢了，按 (repo, point_id) 能匹配的恢复；匹配不上的标 STALE，不删用户任务正文。

### 不做什么

- 不改 `LinkSourceType` 去硬接 Codex（评测与笔记双链语义分开）。
- 不在 `memo` 表加一堆可空 Codex 列当主存储。

### 验收

改路径把某 MUST 删掉或后移，对应任务出现在「过时」；点任务能回到该站。全量重建后 ACTIVE 投影与路径窗口一致。

## G5 · 对话可以提议改路径/要点，人确认后写回 Git

### 现状

`study` 只读。`curate` 只能写 `docs/notes/**` 与 create-only 的 paper-notes/checkpoints。`learning-guides` 禁止 `doc.write`。README 不在白名单。`scope.set` 只改 DB。对 guide 唯一允许的改动是插一行速记。

### 方案：路径文件是唯一可改的体系骨架；新工具不碰教材正文

`DocWriteGuard` 增加第三类 glob（默认）：

`codex.write.path-files=docs/learning-path.md`

语义：**REPLACE 仅限此文件**，且必须：

- 在 `lattice/` 分支；
- `requiresConfirm=true`；
- 写入后跑解析器，`PARSE_FAILED` 则拒绝落盘（或落盘到 `.draft` 不改权威文件——选后者更安全：权威文件只在 parse OK 时替换）。

新工具（tag 含 `codex` + `write` + **`path`**，不含 `task`/`doc`）：

| 工具 | 作用 |
|---|---|
| `path.read` | 返回当前站、要点、version（STUDY 也可见：只带 `codex,read,path`） |
| `path.propose` | 入参：自然语言或 PATH_DELTA；**只返回补丁 + 预览，不写盘** |
| `path.apply` | 入参：补丁 id 或完整文件；确认后写路径文件、sync、触发投影（G3） |

`scope.set`：**废弃写 DB 冒充权威**。改为生成「把该点 MUST↔SKIP」的 `path.propose`。在过渡期若保留 API，必须标明 `overlay-only` 且 UI 默认关闭。

`doc.insert_backref` 增加可选 `point_id`：速记行带 `<!-- point:s1.p1 -->`，沉淀与要点挂钩（G8 同源）。

### 不做什么

- 不开放 `doc.write` 到 `learning-guides/`。
- 不让 `path.apply` 跳过确认。
- 不在 STUDY 里放 `path.apply` / `path.propose`（提议也是贵操作且会改变后续 apply；propose 可放 CURATE/ITERATE，STUDY 只 `path.read`）。

### 验收

对话：顺序错了 → `path.propose` 预览调换两站 → 人确认 `path.apply` → 文件与 `kb_station` 顺序变，教材正文 hash 不变。解析不通过的 apply 被拒。

## G6 · 学习现场能对话，且能选对模式

### 现状

`/codex*` 无 `agent-panel`。下拉只有 Chat / 自动规划 / 复盘。后端已有 study/curate/verify，UI 选不着。默认 Chat 时 Codex 工具全关。

### 方案：五页挂上面板；下拉补三种；按页给默认

1. 五份 Codex 模板加 `.lp-page-shell` + `fragments/agent-panel`（分栏问题仍受 P-UI-001 约束，但**不能再缺面板**）。
2. 下拉增加：研读 `study`、整理 `curate`、验收 `verify`。Chat/规划/复盘保留给 Dashboard。
3. 默认模式：`/codex` 与定线 → `study`；策展/蒸馏 → `curate`；检验 → `verify`；缺口 → `curate`（要 apply 路径补丁）。
4. 用户改了模式，写入 `localStorage` 的 key 按「页面组」分，避免在检验页残留 `curate` 导致看不见 `checkpoint.run`。

P-UI-001 未关闭前：Codex 页允许先 overlay 也能聊；分栏修完后走同一套 shell。不要等 P-UI-001 才加面板。

### 不做什么

- 不把 study 做成第四个 Dashboard 思维模式。
- 不在 Chat 模式泄漏 Codex 写工具。

### 验收

打开 `/codex/distill` 能聊天，默认 curate，能 `path.propose`（开关打开时）。打开 `/codex/checkpoints` 默认 verify，能 `checkpoint.run`，不能 `doc.write`。下拉里能看见 study/curate/verify。

## G7 · 一条对话走完 \(T\)，但不破坏模式隔离

### 现状

Idea 要同一轮：问清 → 改要点 → 更新任务。`plan` 看不见 Codex；`curate` deny 了 `task.*`/`goal.*`，只靠 `gap.to_learning_plan` 旁路建目标；`verify` 不能写；`study` 不能写。

### 方案：新模式 `iterate`，而不是把 task.create 塞进 curate

新增 `AgentMode.ITERATE`（`iterate` / 「学习迭代」）：

| | 值 |
|---|---|
| allow | `codex`, `kb`, `note`, `read`, `write`, `path`, `subagent`, `mcp` |
| deny | `exec`, `insight`, `planner`, **`task`**, **`goal`**, `doc` |

说明：

- 能 `doc.search` / `kb.semantic_search` / `path.read` / `path.propose` / `path.apply` / `doc.write`（笔记）/ `doc.insert_backref`。
- **不能** `task.create`、`goal.create`、`planner.draft_goal_plan`、`checkpoint.run`。
- 任务变化只通过 `path.apply` → `PathProjector`（G3）。这是「整理时不顺手改任务」的原约束，改成「只能经路径改任务」。
- `distill.draft` 仍带 `doc` tag，ITERATE deny `doc` 则蒸馏保持在 `curate`。迭代日常不默认烧 5～9 次 LLM 做蒸馏。

CHAT/PLAN/LEARN/REFLECT：**不加** `path` 到 allow，并在 `Tags.CODEX_FAMILY` 增加 `path`，以免 OR 语义泄漏。

UI：G6 下拉在 Codex 页用「学习迭代」替换「整理」作为定线/路径页默认；策展页仍 `curate`（蒸馏、CI、开 PR）。

### 不做什么

- 不合并 verify（exec 必须单模式）。
- 不改 CHAT/PLAN 的 allow/deny 去「图省事」。
- 不保留 `gap.to_learning_plan` 的 Goal 旁路（G3）。

### 验收

`iterate` 下列表含 `path.apply`、`doc.write`、`doc.search`，不含 `task.create`、`checkpoint.run`。`exportSchemas(chat)` / `exportSchemas(plan)` 字节与改前一致（或仅文档载明的无害差——目标是零差）。apply 路径后 Dashboard 任务变，对话里没有直接建任务。

## G8 · 认可的知识进 Git；检索能同时看见两套，但不混权威

### 现状

`note.create` / `kb.*` → MySQL PKM。`doc.write` / `doc.search` → Git。学习模式 Dashboard 仍是前者。点头不会把随手记搬进仓库。

### 方案：晋升工具 + 联合检索包装，索引仍分源

| 工具 | 行为 |
|---|---|
| `note.promote` | 入参 PKM note id + 可选 `point_id`；渲染为 `docs/notes/*.md`（走现有 `DocWriteGuard` notes 白名单 + 确认）；写完可选 `insert_backref` 到该要点；**不删** PKM 原文，只标 `promoted_path` |
| `search.both` | 内部调 `doc.search` + `kb.semantic_search`，命中带来源标签 `GIT` / `PKM`。新工具，不改旧两个的 schema |

`iterate` / `study` allow `search.both`（tag：`read`,`codex`,`kb`）。LEARN 仍只有 `kb.*`，避免学习模式 cassette 变。

沉淀默认挂 `point_id`（G5）。未晋升的 PKM 不得出现在路径文件里。

### 不做什么

- 不把 PKM 表迁进 Git（随手记继续可以脏）。
- 不改 `kb.semantic_search` 去搜 Git（评测盒）。

### 验收

学习模式随手记仍在 MySQL；`note.promote` 后仓库有对应 notes 文件且索引 `doc.search` 能命中；`search.both` 一条回答里能区分来源。未 promote 的笔记不进 `learning-path.md`。

## G9 · 仓库变了，软件展示必须跟上

### 现状

界面读 MySQL 索引。外部 `git pull` 后须点「增量同步」。UI 默认 `pull=false`。`codex.sync.auto-pull-minutes` 只有设计文档，代码无调度。本地 provider 不 pull。缺口表不能从 Git 重建。

### 方案：读盘同步自动化；远程 pull 仍保守

1. **进入 Codex 工作台或 Dashboard（已接入仓库）时**自动 `sync(full=false, pull=false)`：只把**当前工作副本**编进索引。外部 pull 只要已经更新了磁盘，打开软件就会反映。这是 LOCAL 与「我在 IDE 里改完切回来」的主路径。
2. **可选**工作副本 `WatchService`（debounce ≥ 1s，聚焦才跑），脏树也索引（与现逻辑一致：dirty 不 pull，但编当前内容）。
3. 远程：仅 `provider=GITHUB` 且工作区干净时，顶栏提供「拉取并同步」；**不**默认定时 pull，避免覆盖未提交实验。
4. 同步失败横幅：索引 `headSha` ≠ `git rev-parse HEAD` 时显示「展示落后于工作副本」。
5. 缺口表：本期不假装可重建；评测进程默认 `codex.gap.enabled=false`（已有动机）。G10 的收敛指标不依赖缺口表。

### 不做什么

- 不在后台静默 `git pull --rebase`。
- 不自动 commit。

### 验收

IDE 改 `learning-path.md` 保存 → 切回软件（或等 debounce）→ 站与要点展示变，不必手点同步。GitHub 干净仓库点「拉取并同步」后 SHA 与展示一致。脏工作区拉取按钮禁用并说明原因。

---

## G10 · 「收敛」可感知，且不可用覆盖率作假

### 现状

有检验通过率、死链、孤岛，没有「路径还在不在大幅改」。P5 若用跳过清单当覆盖率分母会假绿。

### 方案：路径文件的 churn 就是收敛信号

每次成功的 `path.apply` 与每次 sync 解析，追加 `kb_path_revision`：

- `version`, `head_sha`, `n_stations`, `n_must`, `n_skip`
- `added_points`, `removed_points`, `reordered_stations`（相对上一 version）

UI 一块「近 14 天路径变动」：点数增减、站顺序是否动过。文案：**变动变小 ≈ 在收敛**；不是分数，没有 100 分。

辅助（可选，机器可判）：当前窗口 MUST 中，已 SATISFIED 的比例。分母是路径上的 MUST（G1），**不是**跳过清单。

### 不做什么

- 不做「体系完整度 0–100」。
- 不把 P5 LLM 综述当收敛。
- 不把检验通过率单独叫收敛（那是假懂卡尺）。

### 验收

连续 apply 三次大改顺序，图表上有三峰；之后只改笔记不 apply 路径，churn 为 0。分母条数与 `learning-path.md` 的 MUST 行一致。

## G11 · 可见产品回到生长回路

### 现状

顶栏：接入 · 定线 · 检验 · 策展 · 缺口。用户看到的是运维面。

### 方案：Tab 按回路改名改序，不新做空页面

| Tab | 路由 | 主内容 |
|---|---|---|
| 路径 | `/codex` 或 `/codex/path` | 当前路径、要点、cursor、churn（G10）；接入仓库收进本页设置区 |
| 学 | `/dashboard` 深链或 `/codex/learn` | **投影任务** + Agent（默认 iterate）；不要再把「学」做成第三套列表 |
| 资料 | `/codex/distill` | 原料列表 + 蒸馏 + 路径补丁预览 |
| 检验 | `/codex/checkpoints` | 不变 |
| 缺口 | `/codex/gaps` | 转计划 = 路径补丁（G3） |
| 策展 | `/codex/curate` | CI、沉淀、分支；从主路径降为「维护」 |

「接入」不再当一级 Tab。Dashboard 顶栏「知识仓库」仍跳出三模式，落到 **路径** Tab。

### 不做什么

- 不为地图/阅读器占位。
- 不把五页合成 SPA（仍多路由 + 共享 chrome）。

### 验收

新用户从 Dashboard 进知识仓库，第一屏是路径/要点（或「还没有路径，去资料蒸馏」），不是健康度卡片当主角。检验/CI 仍在，但不在第一位。

## G12 · 默认关着不等于产品不存在；打开方式按「已接入仓库」而不是一把全局刀

### 现状

`codex.enabled` 等默认 `false`。合理处：评测会污染缺口、写入会改用户磁盘。不合理处：连只读路径都没有。

### 方案：分层默认

| 开关 | 建议 |
|---|---|
| `codex.enabled` | 保持全局可关；**一旦用户在 UI 接入仓库**，对该用户视为开启只读（索引+路径展示+定线），不必先改 `application.properties` |
| `codex.write` / `distill` / `exam` / `verify` | 仍默认关；在路径页用明确的「允许写入工作副本」开关，写进用户偏好而非全局文件 |
| `codex.gap` | 默认关；评测 JVM 强制 false |

实现上：`RepoRegistryService.enabled()` 对「已有 KnowledgeRepo 行的用户」返回 true，全局 false 仍可一键停掉全站。写入仍走 `codex.write.enabled` 或等价的 per-user 偏好。

### 不做什么

- 不把 write/gap/distill 默认 true。
- 不靠文档叫用户改 properties 才能看见路径。

### 验收

新用户只点「接入」，不改配置文件，能看见索引和「尚无路径」。未开写入时 apply/沉淀仍有横幅。`gradlew test` 默认缺口仍不落库。
