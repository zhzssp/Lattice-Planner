## 1. 接入仓库后 Git 检索仍关着（G8 / G12）

| 项 | 内容 |
|---|---|
| 状态 | **代码已合上**（2026-09-16），待真仓库点一次 `doc.search` / `search.both` |
| 用户会遇到什么 | 路径页、索引、文件浏览都在，Agent 搜仓库却是空的 |
| 根因 | `pkm.rag.git.enabled` 默认 `false`（评测不要走 Git、以免 CRAG 灌假缺口）；G12 让接入即只读，检索闸门没跟着改 |
| 不要做什么 | 不要把 properties 默认改成 `true` |

### 做法

`CodexSearchService.searchable(userId)` = 配置为 true **或** `RepoRegistryService.readable(userId)`。`enabled()` 仍只反映配置项，给观测面板和评测看。`doc.search` / `search.both` 走 `searchable`。

评测进程通常不接入仓库，GIT 侧继续空，cassette 不受影响。

### 验证记录

（空。关闭时写明：接入某仓库、`pkm.rag.git.enabled` 仍为 false、`doc.search` 与 `search.both` 的 GIT 侧有命中。）

## 2. 止损线召回仍读 guide 跳过清单，不是 `kb_point(SKIP)`

| 项 | 内容 |
|---|---|
| 状态 | **未做**（有路径文件、且路径 SKIP 与教材清单分叉时再做） |
| 用户会遇到什么 | 路径表里标了「先跳过」的要点，提问时不一定被召回；教材里的「先跳过」术语仍会召回 |
| 根因 | P3 `ScopeRecallService` 扫 guide → `kb_entity`；G1 把 SKIP 写进 `kb_point`，召回没改读 |
| 不要做什么 | 不要整表换成只读 `kb_point`。现有仓库大多还没有 `learning-path.md`；SKIP 行是整句，拿整句做词边界几乎永远打不中 |

### 要不要做

要。这是 G1 写明的纪律收口，不是日常立刻会断的洞。覆盖率分母已经改成路径 MUST；召回还挂在旧清单上。

### 做法

- **有路径文件时**：从 SKIP 行抽出反引号/粗体术语（复用 `ScopeListParser` 抽词），编进召回表。`kb_scope_decision.hitCount` **禁止清零**。
- **没有路径文件时**：继续用 guide 清单，UI 标明「来自教材止损线，尚未写入路径」。
- 同一术语两处都有 → 一条决策，出处写路径优先。
- `kb_entity` 可以暂时仍挂召回行，不必先删表。

## 3. 既有 README 阶段表不会变成路径草稿

| 项 | 内容 |
|---|---|
| 状态 | **未做**（接到「路线已经写在 README」的真仓库时再做） |
| 用户会遇到什么 | 接入后看到「尚未抽出路径」，必须蒸馏 PATH_DELTA 或手写 `docs/learning-path.md` |
| 根因 | G1 写了第一期只读导入；权威改成路径文件后，导入没做 |
| 不要做什么 | 不要覆盖已有权威文件；不要用 guide 目录猜车站；解析失败不要静默丢行 |

### 要不要做

对往后的 T(x) 回路不是缺陷：权威本来就是路径文件。只是给 AI-Infra 这类已有 README 阶段表的仓库少一次手抄。

### 做法

窄口径解析 README 阶段表 → **只新建** `docs/learning-path.md.draft` → 人核对后 `path.apply`。读不了就明示，不要假装抽出了路径。

## 4. 未晋升的 PKM 不得进路径文件（只写在工具说明里）

| 项 | 内容 |
|---|---|
| 状态 | **纪律层**（解析器不要去扫笔记标题） |
| 用户会遇到什么 | iterate 里模型把随手记标题写成 MUST 行，人点了 `path.apply` 确认，脏笔记就进了权威文件 |
| 根因 | G8 验收写了「未 promote 的笔记不进 `learning-path.md`」；实现只在 `note.promote` / `path.propose` / `search.both` 的描述里约束 |
| 不要做什么 | 不要让 `LearningPathParser` 读 PKM。标题碰巧相同是合法的，硬拒绝会误伤 |

### 要不要做

`path.apply` 已经要人确认。机器帮一眼即可，不是回路正确性。

### 做法

`path.propose` 预览时，把要点原文和**未** `promoted_path` 的笔记标题做精确匹配；命中则警告「这条还是 PKM，请先 `note.promote`」，不拒绝写入。

## 5. 出题 front-matter 不写 `station_id`

| 项 | 内容 |
|---|---|
| 状态 | **未做**（单独加字段没有读者） |
| 用户会遇到什么 | 检验条目和路径车站对不上；L2 通过也不会自动把对应 MUST 标成 SATISFIED |
| 根因 | G2 写了「guide 声明了 `station_id` 就写入 checkpoint」；设计原文同时说不阻塞 G2。投影 SATISFIED 目前只看任务是否 DONE |
| 不要做什么 | 不要先改出题模板却不改 `PathProjector` |

### 要不要做

要补就整条链一起做。只写出题字段，覆盖率和投影都不会变。

### 做法

guide 声明 `station_id` → `ExamService` 写入 checkpoint front-matter → `PathProjector` 在该站有 L2 通过时把对应 MUST 标 SATISFIED（任务仍可 DONE）。
