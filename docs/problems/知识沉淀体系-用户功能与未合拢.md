## 1. 用户视角：这套东西是干什么的

Lattice 里其实有**两套知识**：

| | 个人笔记（PKM） | 知识仓库（Codex） |
|---|---|---|
| 入口 | Dashboard →「我的笔记」 | Dashboard →「知识仓库」 |
| 权威源 | MySQL 里的笔记 | **你本机的 Git 仓库** |
| 典型内容 | 随手记、标签、语义搜索 | learning-guides、checkpoints、notes、论文 PDF |
| 软件承诺 | 帮你搜到自己写过的话 | 帮你**执行一套学习纪律**（先预测再跑、示例不能砍、跳过的东西会被召回） |
| 离开软件 | 笔记留在库里 | 仓库用 IDE / Obsidian 照样打开 |

Codex 不是「又一个笔记 App」。产品文案自己的定位是：

> 仓库是唯一权威源，本地数据库只是可重建的检索索引。随时能脱离本软件。

对用户来说，它要解决的是自学/知识工作里这几件 Notion、Obsidian 不管的事：

- **我现在该干什么**（对照路线表，而不是打开仓库发呆）
- **怎么证明我不是「看懂了」**（检验：先写预测，再跑脚本）
- **对话里搞懂的东西怎么沉回主文档**（短笔记 + 挂一条「速记」引用，主文档保持可扫读）
- **我当初标「先跳过」的概念，后来是不是一直在挡路**（被反复问到才提醒补课）
- **Agent 不许直接改 main**（改动落在 `lattice/` 分支，人看 diff 再决定）

## 2. 用户实际走的五张页面

全部挂在 `/codex` 顶栏。Agent 聊天面板**目前不在这些页面上**（见 P-UI-001 的范围说明）。

```
/codex                 接入仓库、看健康度
/codex/distill         我现在该干什么 + 蒸馏 PDF + 出题
/codex/checkpoints     先预测，再跑检验
/codex/curate          知识体检、沉淀笔记、看分支 diff
/codex/gaps            缺口台账、止损线、转成学习任务
```

### 2.1 知识仓库首页 `/codex`

用户做的第一件事：填**已有 git 工作副本的本地路径**（例如 `AI-Infra`），选「学习」或「工作」，点「接入并建立索引」。

接入**不改仓库里任何文件**，只读内容建检索索引。之后可以看到：

- 文档 / 章节 / 切片数量
- **被截断**的文档（太长，索引只吃了前半段——搜不到不代表原文没写）
- **死链**、**孤岛**（没有任何链接指向的文档）
- 增量同步命中率（长期为 0 要怀疑哈希没算对）

日常操作：增量同步、全量重建、移除接入。全量重建用来证明「删掉派生索引也能从 Git 再长出来」。

「工作」这个选项在表单里已经有，但 **WORK 模板包（P7）还没做**，选了也不会换成工单/设计文档那一套检验。

### 2.2 蒸馏与定线 `/codex/distill`

这是「每天打开软件」时最该看的一页，分三块。

**我现在该干什么**  
点「重新计算」。不调 LLM，根据库里已有记录排出下一步，每条都带**可点开核对的依据**。例如：有未核对的蒸馏草稿、有检验还没填预测、有失败的检验该去修、有被问了三次的缺口该补。它会如实写 caveat：只依据库里已有记录；某主题没有 lab 就出不了可执行的题。

**读 → 做 → 验（阶段表）**  
把仓库路线拆成：读哪篇 guide、有没有对应 lab、检验过到哪一级。L2（加一个组件并跑出差异）是主判据；L0 只是跑通既有脚本。

**蒸馏：原料 → Guide 草稿**  
从仓库里的 `paper/*.pdf`（或 md）起草一篇学习笔记草稿。落盘只能**新建**文件（`docs/paper-notes/`），不能覆盖你已经手写的精读。产物带 `maturity: draft`，必须人核对。公式和配图会丢，这是 PDF 抽文本的原理限制，不是漏做的按钮。

**出题：Guide → 检验草稿**  
给一篇有 lab 的 guide 出几道可跑的题，写到 `docs/checkpoints/`，同样只能新建。机器出的题在检验面板上会标「判据未经人工验证」。

这两项默认关（`codex.distill.enabled` / `codex.exam.enabled`），因为一次起草要打 5～9 次模型，贵，且会往仓库加文件。

### 2.3 知识落地检验 `/codex/checkpoints`

用户问题是：**怎么证明我会，而不是我觉得我会。**

流程强制是：

1. 打开一条检验（L0 复现 → L1 改一处 → L2 加组件 → L3 打通）
2. **先写预测**（不填则「运行」按钮锁死；提交后冻结，不能改）
3. 软件在受限环境里跑仓库里的脚本
4. 机器看退出码等通过标准
5. 人再判定：通过且预测对 / **通过但预测错**（最有价值：结果对、因果想错了）/ 失败

预测错不扣分；预测错却没发现自己错了，才是问题。通过但预测错，软件会建议去策展页沉淀一篇笔记。

默认要开 `codex.verify.enabled`。多数从 Markdown 解析出来的题，机器只能看到「脚本是不是 exit 0」，精细的 `expect` 还弱——用户会感觉「能跑」和「真懂」之间仍有缝。

### 2.4 知识策展 `/codex/curate`

整理仓库，不跑检验、不改任务列表。

**知识 CI（只读）**  
九项检查：死链、双向引用、笔记里有没有示例、front-matter 等。`SKIPPED` 表示**没检查**，不是通过。写入关闭时，CI 仍然能跑——设计就是「先相信报告，再给改文件的权限」。

**沉淀一篇笔记**  
把对话里真正搞懂的一段，写成 `docs/notes/` 短文，并在主 guide 对应章节挂一条「速记」引用（主文档保持可扫读）。正文里必须留下代码 / IR / 对照表，砍成一句话摘要会被拒绝（`MISSING_EXAMPLES`）。写文件默认不提交；提交走下面的工作分支。

**工作分支与审阅**  
改动落在 `lattice/` 前缀分支，可看 diff、丢弃分支、按配置开 PR。软件**不替你 merge**。开了 PR 之后合没合，当前也不回读。

写入总开关 `codex.write.enabled` 默认关：打开才会真实改你的 git 工作副本。既有 `docs/learning-guides/` **整目录禁止写**，避免 Agent 改你的教材。

### 2.5 知识缺口 `/codex/gaps`

缺口不是「Agent 觉得你该学 X」，而是**行为证据**：

| 来源 | 用户侧含义 | 补法 |
|---|---|---|
| CRAG | 问了，库里答不上来 | 补资料 |
| SKIP_RECALL | 当初标了「先跳过」，后来反复被问到 | 把跳过的概念补进主文档 |
| CP_FAIL | 检验没跑过 | 补动手 |
| CP_MISPREDICT | 检验过了但预测写错 | 补因果理解（和「做不出来」几乎相反） |

用户可以：按被问次数排序看台账、转成学习计划（生成目标+任务）、关闭时必须指出证据文档、或判定「这不是我的缺口」予以 dismiss。

另有一块**止损线**：列出各 guide 里「可以先跳过」的术语，以及被遇到的次数。达到阈值才登记缺口，避免偶遇就报警。

默认 `codex.gap.enabled=false`。原因不只是谨慎：评测套件也会走检索工具，开着跑评测会往台账灌假缺口，而缺口表**不能从仓库重建**，污染洗不掉。

## 3. 和 Agent 对话时，用户会碰到什么

聊天面板的模式决定 Agent **允许碰知识仓库的哪一层**（执行层强制，不是靠提示）：

| 模式 | 用户意图 | 能做 | 故意不能做 |
|---|---|---|---|
| `study` | 研读 | 搜仓库、读文档、搜个人笔记 | 写文件、蒸馏、跑脚本、改任务 |
| `curate` | 整理 | 沉淀、挂引用、开 PR、蒸馏/出题（若开关打开） | 改任务/目标、跑检验脚本 |
| `verify` | 验收 | 跑 checkpoint（唯一能执行命令的模式） | 写文档、改任务 |

个人笔记检索走 `learn` / 普通 `chat` 里的 `kb.*` / `note.*`，和 Codex 不是同一个搜索框。用户不会自动得到「笔记 + 仓库」合成的一次回答——这是后面缺口的一部分。

## 4. 一条完整日常路径（开关都打开时）

用户视角的「完整一天」应当是：

1. `/codex` 增量同步，看死链/截断有没有恶化  
2. `/codex/distill` 看「我现在该干什么」  
3. 读它指出的 guide（在 IDE 里打开仓库，软件不自研编辑器）  
4. `/codex/checkpoints` 填预测、跑一条 L2  
5. 若预测错或对话里出现新理解 → `/codex/curate` 沉淀笔记并挂引用  
6. 知识 CI 绿了再看 diff / 开 PR  
7. `/codex/gaps` 里被问了三次的跳过概念，转成一条学习任务  

今天这条路径在代码上**基本能串**，但：

- 总开关和写/缺口/蒸馏默认全关，不开等于没有这套产品；
- 第 6 步停在分支上，合回权威源要用户自己去 GitHub/本地 merge；
- 没有「知识地图 / 覆盖率 / 同构表」这种「我的体系长什么样」的页面。

## 5. 未合拢的问题（相对用户承诺）

这些是用户会感觉到的空洞，不是内部表名清单。

| # | 用户会遇到什么 | 根因（一句话） |
|---|---|---|
| 1 | 打开产品，知识仓库是灰的 | `codex.*` 默认 false，能力不是默认体验 |
| 2 | 没有「我的知识体系」总览，只有单篇文档和检验列表 | P5 未做；entity 目前几乎只来自「先跳过」清单，覆盖率分母会骗人 |
| 3 | 笔记页搜不到仓库 notes，对 Agent 说「搜知识」要自己选模式 | PKM 与 Codex 两套索引 |
| 4 | 沉淀完、PR 开了，软件不再过问 | 不 merge、不回读 PR/Issue |
| 5 | 检验「过了」仍心里没底 | 大量题只能判退出码；机器出题标了未经人工验证 |
| 6 | 选了「工作」仓库，流程仍像学习仓库 | P7 WORK 模板包未做 |
| 7 | 官方文档更新了，guide 不会标过期 | P6 策展/腐化未做 |
| 8 | 不知道这套东西在自己的真仓库上好不好用 | P0～P4 实施记录写明待真机验收 |

**不要用「再让 LLM 写一篇 foundations」来关本题。** 那和 P4 蒸馏同类，且覆盖率会假绿。

---

## 6. 怎样才算关闭本题

最低关闭条件（用户路径，不是夹具测试）：

1. 用一份真实学习仓库（如 `AI-Infra`）打开 `codex.enabled` 及必要子开关，按 §4 走完一天，过程可截图/录屏。  
2. 「我现在该干什么」给出的每条下一步，用户能点进对应文档或检验。  
3. 沉淀后主 guide 出现速记引用，笔记里保留示例；既有 paper-note / guide **不能被覆盖**。  
4. 缺口只来自真实提问/检验，不来自评测套件。  
5. 明确写出仍未做的 P5～P7 为**后续题目**，不再混在「沉淀体系已完成」的表述里。

更完整的关闭还要：entity 分母改为 foundations 结构化清单、PR 合并状态回读、PKM+Codex 一次检索。可拆后继问题，不必堵在这一篇里一次做完。
